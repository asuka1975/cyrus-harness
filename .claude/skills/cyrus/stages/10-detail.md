# ステージ10: 見せ方を決める（Document Detail Design）

フェーズ: 組み立て 4/5　成果物: `10-detail.json`　承認: 不要

## ねらい

節ごとに、内容を**文章で書くか、箇条書き・表・図・例で見せるか**を決めます。
図と表は、visual-patterns スキルで「読み手に何を読み取らせたいか」から決めます。見た目や思いつきで図を置きません。
あわせて、その節で新しく導入する用語と、想定する字数を決めます。書く前に決めておくと、書きながら迷わず、分量も読者の時間に収まります。

## 文章の形の選び方

| 内容の性質 | 向いている表現 |
| --- | --- |
| 理由・因果・背景（つながりを伝えたい） | 文章（prose） |
| 並列の項目（順序に意味がない、3〜7個） | 箇条書き（list） |
| 順序のある作業（主体が一つで、分岐がない） | 番号付きの手順（steps） |
| 抽象的な説明の理解を助ける | 具体例（example） |
| 注意・補足（読み飛ばしてもよい） | 囲み（callout） |
| コマンド・設定 | コード（code） |
| 読み手に読み取らせたい答えがあり、根拠に形がある | 図（figure）か表（table）。次の節の手順で決める |

## 図と表の決め方（visual-patterns）

図表は「答え」と「根拠の形」の対です。答えは文章（キャプション）が言い、図表は根拠の形を見せます。答えのない図表は、読者の視線を散らすだけなので入れません。

節ごとに、次の順で進めます。

1. **答えと根拠を手元に置く。** 答えの候補は `09-storyline.json` の message（その節で読者が持ち帰る一文）です。根拠は、その節に割り当てた主張（`05-claims.json`）と事実（`06-facts.json`）、ステージ4で選んだ情報、`08-structure.json` の節の `elements`（構成スキルが挙げた「入れる要素」）です。根拠には**数を添えます**（値がいくつ、対象と観点がいくつ、主体と段階がいくつ、条件がいくつ）。
2. **根拠の形を当てはめる。** 次のどれかに当たれば図表の候補、どれにも当たらなければ文章です（visual-patterns の手順2）。
   - 量: 答えが述べる値が 5 つ以上。または 2 区分 × 2 時点以上の増減・差が答えで、差の大きさが要る
   - 項目×属性: 対象 2 以上 × 観点 3 以上、または対象 5 以上 × 観点 2 以上
   - 段階・主体・部分: 主体が 2 つ以上あり段階と合わせて 4 つ以上。または分岐・合流・循環・多対多・入れ子を含む。または前後関係と相対の期限が答え。または渡るたびに減る・変わることが答え
   - 条件と結果: 条件が 2 つ以上あり、どれに当たるかで結果が分かれる
   - 外観: 見た目が答えで、言葉では特定できない

   値が 4 つ以下の比較、一つの定義や理由、主体が一つで分岐のない手順、3 つ以下の列挙は文章にします。迷ったら根拠を文章で書き出し、同じ文型が 3 つ以上並ぶか、読者が前の文に戻って照合し直すなら図表にします（その判断で目安に満たない根拠を図表にするときは、spec の `evidence.below_threshold_reason` に `repeated-pattern` か `cross-reference` を書く）。
3. **図表にする節は、Skill ツールで `visual-patterns` を呼びます。** 渡すものは次のとおりです。
   - 答え（一文）と、その節の問い（`08-structure.json` の reader_question）
   - 根拠（数を添えて）。値があれば値そのもの
   - 読者: `03-reader.json` の knowledge_level と、記法の知識（known_terms にフローチャートやシーケンス図などがあるか）
   - 精度（正確な値が要るか、傾向でよいか）と読み方（通読 through か参照 lookup か。`03-reader.json` の reading_context.reading_mode が reference（必要なときに引く）なら参照、purpose が lookup（調べる）の文書も参照に寄せる。それ以外は通読を基本にし、表引きのための表など節ごとに変えてよい）
   - 媒体: Markdown。Mermaid はそのまま表示でき、PNG の画像も置ける
   - 返してもらうもの: **figure spec（JSON）と作図判断**。本文は書かせない
4. **返ってきた spec を、その節の figure / table ブロックの `spec` に入れます。** `plan` には何を見せるかを一言で書きます。
5. `cyrus check` が spec をカタログの規則で検査します（VP0xx）。
   - **VP020** は「手順2 の目安では文章」です。根拠の数を水増しせず、文章にします（根拠を書き出して照合し直す必要があると判断したときだけ、`below_threshold_reason` を書いて図表にする）。
   - **VP053** は、正確な値を読ませたい（precision: exact）のに概観のパターンを選んでいます。表にするか、概観の図と値の表に分けます。
   - **VP031** は根拠の形と趣旨が合いません。**VP041** は候補にないパターンです。趣旨か候補を選び直します。
   - **VP071** はこのスキルで描けないパターンです。別の候補か、表か文章にします。**VP074** は `render` がそのパターンの描き方と違うだけなので、`render` を直します。**VP073**（警告）は、その描き方の注意（日本語ラベルの制限など）です。

図表の数は、節の数とは無関係です。根拠に形のある節にだけ図表が付き、結果として図のない節が多くて構いません。

ユーザーに確かめたいときは、専門用語を使わずに聞きます（例:「この節を読み終えたとき、読者の頭に一目で思い出せる『形』として残ってほしいものはありますか」「ここで読者は『どれがどれにつながる？』『どっちが大きい？』『何が変わった？』のどれを聞きそうですか」）。答えがそのまま spec の答えと根拠になります。

## 新しく導入する用語（new_terms）

- 読者が知らない語（03-reader.json の `unknown_terms`）を使うなら、最初に使う節の `new_terms` に入れ、1文の定義を書く。
- 1つの節で導入する語は、読者の知識レベルごとの目安（初心者3個・中級者4個・専門家6個）までにする。超えるなら節を分けるか、語を減らす（言い換えられる語は言い換える）。
- ここに入れた語は、ステージ13で「初出で説明されているか」が検査されます。

## 字数

- `target_length_chars` に全体の目標字数を書く。読者の使える時間（time_budget_min）× 読む速さ（初心者400字／分・中級者500字／分・専門家600字／分）が上限の目安。
- 各節の `length_chars` は、その節の役割の重さに比例させる。要約は短く（全体の1割程度）。`08-structure.json` の節に `length_hint`（構成スキルの目安）があれば、それに合わせる。

## 成果物 `10-detail.json`

```json
{
  "target_length_chars": 3000,
  "sections": [
    {
      "id": "S1", "heading": "要約",
      "blocks": [
        {"kind": "prose", "plan": "結論と依頼を2文で"},
        {"kind": "list", "plan": "判断材料を3点"}
      ],
      "new_terms": [],
      "length_chars": 300
    },
    {
      "id": "S3", "heading": "仕組み",
      "blocks": [
        {"kind": "figure", "plan": "記事が保存されてから検索に出るまでの流れ",
         "spec": {
           "question": "記事はどこで待たされるのか",
           "answer": "記事は夜間の索引づくりを待ってから検索に出る。",
           "evidence": {"form": "parts-relations", "description": "主体 3（保存・索引づくり・検索）、段階 4、待ちが 1 か所",
                        "counts": {"actors": 3, "steps": 4}, "features": []},
           "precision": "overview", "reading": "through",
           "intent": "step-order", "pattern": "sequence-diagram",
           "drawing": "待ちの区間だけ色を付け、「翌朝まで」と注釈する",
           "render": "mermaid"
         }}
      ],
      "new_terms": [{"term": "インデックス", "definition": "検索を速くするために、記事から作っておく索引"}],
      "length_chars": 600
    }
  ]
}
```

- `kind` が figure / table のブロックには `spec` が必須です。spec の項目と語彙は visual-patterns の SKILL.md にあります。
- 図は文書に現れる順に 図1、図2…、表は 表1、表2… と番号が付きます（ステージ11で、この順でキャプションを付けます）。
