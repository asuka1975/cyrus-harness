# 探し方を組み立てる（ステージ6と cyrus-fact-checker が読む）

公開情報で確かめる仕事（事実の確認、命題の証拠探し、広く使われているかを数える）で、探し方をどう決めるかの手順です。
決まった当たり先の一覧ではありません。命題ごとに、次の順で探し方を組み立てます。

## 1. 何があれば決まるかを先に言う

命題を見て、「どんな証拠が出てくれば、この命題は支えられる（または崩れる）か」を一文で書きます。証拠の種類で、探し方が決まります。

| 証拠の種類 | 例 |
| --- | --- |
| 規則・仕様・公式の決まり | 「本人は自分のプルリクエストを承認できない」 |
| 数字（統計・調査・計測） | 「回答者の 62% が検索に不満」 |
| 研究で分かっていること | 「翻訳調の文は読む時間が長い」 |
| ある言い方・経験が広く共有されていること | 「〜はよくある言い方だ」「〜で困る人は多い」 |
| 記録に残っていること | 「障害は 3 件起きた」 |

## 2. その証拠は誰が作り、どこに溜まるかを考える

証拠の種類ごとに、作る人（機関・コミュニティ・研究者・自分たち）と、溜まる場所（公式ドキュメント、統計の原典、論文のデータベース、その言い方が使われる場所そのもの、手元のログ）を挙げます。
「広く共有されているか」の命題は、**その言い方や経験が実際に現れる場所**で数えます。技術者の言い回しなら技術記事の置き場、業務の言い方なら企業や自治体の文書、学術の言い方なら論文です。一般の検索エンジンは、場所を特定したあとの入口の一つにすぎません。

## 3. その場所に届く道を選ぶ

近い順に試します。

1. **場所自身の検索。** そのサイトやサービスの検索機能や公開 API。語句をそのまま含むものを数えられ、期間で絞れることが多い。使う前に、API の有無と利用上限を確かめる。
2. **場所を絞った Web 検索。** WebSearch の `allowed_domains` にその場所のドメインを入れる。
3. **コーパス・辞書。** 語義や用例（辞書）、頻度（少納言・BCCWJ など）。
4. **手元の記録。** `records` に渡された場所を Grep か短いスクリプトで数える。
5. **一般の Web 検索。** 上のどれでも届かないとき、または場所を探すとき。

検索語は 2〜4 語で、1つの概念ずつ。そのままの形を探すときは半角の二重引用符で囲む（`"承認が下りる"`）。鉤括弧「」や「以外」は検索の記号ではない。言い換えや周辺語を1つの検索語に詰め込まず、知りたいことが3つなら3回引く。日本語と英語の両方で引く。1回目が薄ければ `extended` を1回。それでも出なければ、検索語を変え続けず、道（上の 1〜5）を変える。

## 4. 道が効いているかを確かめてから数える

0 件を信じる前に、**あるはずのもの**で同じ道を試します（正の対照）。たとえば、その場所で確実に使われている別の言い方を同じ方法で引き、件数が出ることを見ます。出なければ、その道は壊れているか、語句の形が合っていないので、道を直してから数え直します。

数えるときは、独立した書き手の数を数えます（転載・まとめは1件）。反対の向き（違和感を書いた人、仕様が違うと書いた人）も同じ道で数えます。`evidence` には、検索語、道（どの場所の何で引いたか）、件数、日付を書きます。

## 5. 見つけたら

ページを WebFetch で読み、該当箇所を短く引用する。参考文献や引用先をたどり、一次情報に届いたらそちらを出典にする。検索結果の要約で判断しない。

## 6. 「見つからなかった」と言う前に

次をすべて済ませてから `not_found` に書きます。

1. 手順1で証拠の種類を決め、手順2で場所を挙げた。
2. 道を2つ以上試した（場所自身の検索か場所を絞った検索を1つ含む）。検索語は短いものを日本語と英語で。
3. 正の対照で道が効くことを確かめた。
4. `searched` に、道ごとの検索語・件数・日付を書いた。

件数が出たら、それは `not_found` ではなく数えた事実です（status は目安に照らして決める）。
