# 読みやすい日本語の指針

cyrus で書く文書の文章指針です。読者の認知負荷を下げることを最優先にします。
各項目の末尾の［ ］は、対応する `cyrus lint` / `cyrus wording` のルール ID です。

## 1. 文

- **1文に1つのこと。** 条件・理由・結論を1文に詰めない。［JA001, JA002］
  - 前: 検索基盤はインデックスを夜間にしか更新しないため、当日に書かれた記事は翌日まで検索結果に表示されず、利用者から不満が出ている。
  - 後: 検索基盤は、インデックスを夜間にしか更新しません。そのため、当日に書いた記事は翌日まで検索に出てきません。利用者の不満はここから来ています。
- **長さの目安は60字以内。** 読者の知識レベルで基準が変わる（初心者60字・中級者70字・専門家80字で警告）。
- **読点は意味の切れ目に打つ。** 50字を超える文に読点がないと、区切りを読者が探すことになる。［JA003］ 逆に読点が5個以上あるなら、文を分ける合図。
- **主語と述語を近づける。** 間に長い修飾を挟まない。
- **修飾語は、長いものを先に置く。**
- **二重否定を使わない。**「〜ないわけではない」→「〜の場合もある」。［JA008］
- **括弧の中を長くしない。** 25字を超える補足は本文に出す。括弧を入れ子にしない。［JA009］
- **漢字を6字以上続けない。**「検索基盤刷新計画概要」→「検索基盤の刷新計画の概要」。［JA004］

## 2. 語

- **読者が知らない語は、初めて出たところで説明する。**［WD002, WD003］
  - 用語（説明）の形:「インデックス（検索を速くするための索引）」
  - 説明を先に言う形:「検索を速くするための索引を、インデックスと呼びます」
- **説明できない語は使わない。** 言い換えで済むなら言い換える。
- **1つの節で新しく出す語は3〜4個まで。** 覚える語が多いと短期記憶があふれる。［ST011］
- **同じものは同じ語で呼ぶ。** 言い換えると、読者は別物かと迷う。表記も揃える（サーバー／サーバ）。［WD007］
- **漢字をひらく。** 接続詞（及び→と、又は→または）、副詞（既に→すでに）、形式名詞（事→こと、為→ため）、補助動詞（して下さい→してください）。［WD005］
- **硬い漢語をやさしくする。** 鑑みる→踏まえる、齟齬→食い違い、喫緊→急いで取り組むべき。［WD005］
- **冗長な言い方を短くする。**「確認することができます」→「確認できます」、「確認を行う」→「確認する」。［WD006］
- 文書全体の漢字の割合は30%前後を目安にする（40%を超えると警告）。［JA005］

## 3. 段落と節

- **節の最初の文で、その節のメッセージを言う。** 拾い読みする読者は、見出しと段落の最初の文しか読まない。
- **1段落は1つの話題。** 長さは200〜250字程度まで（読む状況で変わる）。［ST004］
- **段落を指示語で始めない。**「これは」ではなく「この遅れは」のように、何を指すかを名詞で書く。前の段落を思い出さなくても読めるようにする。［JA010］
- **「後述」「前述」を減らす。** 読者に記憶の保持や視線の移動を求めることになる。その場で書くか、節の名前で示す。［JA011］
- **小見出しなしで1500字を超えない。**［ST005］
- **同じ文末を3回続けない。**「〜しています。〜しています。〜しています。」は単調で、区切りが見えにくい。［JA007］
- **文体を混ぜない。** です・ます体か、だ・である体のどちらかに揃える（箇条書きや表の中の体言止めは可）。［JA006］

## 4. 見出し・箇条書き・表・図

- **見出しは短く（30字以内）、内容がわかる語にする。**「その他」「概要」だけの見出しは避ける。［ST008］
- **同じ階層の見出しは形を揃える。**［ST012］
- **見出しのレベルを飛ばさない。**［ST001］
- **箇条書きは7項目まで、入れ子は2段まで。** 項目の形（名詞止め／文）を揃える。［ST006］
- **表は6列・12行まで。** それ以上は分けるか、要点だけにする。［ST007］
- **図表には番号とキャプションを付け、本文から参照する。** 参照されない図表は、読者がいつ見ればよいかわからない。［ST010］
- **図は、言葉で書くと長くなる構造・流れ・位置関係にだけ使う。** 装飾の図は視線を散らす。

## 5. 主張の強さ

- 主張は、`07-logic/report.json` の確信度（hedge）に合わせて書く。
  - assert: 言い切る。「〜です」
  - moderate: 根拠を添えて。「〜のため、〜と考えられます」
  - tentative: 可能性として。「〜の可能性があります」
  - hypothesis: 主張にしない。「未確認ですが、〜という見方もあります」
- 判断の主体をぼかさない。「〜と思われる」ではなく「〜と考えます（筆者）」「〜と報告されています（出典）」。［WD006］
- 数字には出典を添える。

## 6. 読む状況への配慮

- **拾い読みされる文書**: 冒頭に要約を置く。各節の最初の文だけで話が通るようにする。
- **引いて使われる文書**: 見出しに検索されそうな語を入れる。各節を単独で読めるようにする。
- **スマホで読まれる文書**: 段落を短く、表の列を4列までにする。
- **読者の時間**: 推定読了時間（字数 ÷ 読む速さ）が、読者の使える時間を超えないようにする。［ST013］
