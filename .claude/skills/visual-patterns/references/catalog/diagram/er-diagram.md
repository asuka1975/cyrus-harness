# ER図

## 定義

データの実体（エンティティ）を枠で描き、実体同士の関係を線で結び、線の両端に多重度（1 対多など）を記号で示した図である。枠の中に属性を列挙し、主キーや外部キーを区別する。記法には IE（鳥の足）や IDEF1X などがある。

## 目的

読み手が「どの実体がどの実体と関係し、一方の 1 件に対して他方は何件あるか」に答えられるようにする。

## どういうときに利用するか

- データベースのテーブル設計を、関係と多重度を含めて正確に共有したい
- 業務のドメインモデルで、実体の属性と識別子を定義したい
- 実体が多対多で結ばれ、文章では関係の数と向きを保持できない（手順2 の「段階・主体・部分とその関係」の行）

## どういうときに利用してはいけないか

- 読み手が多重度の記法を知らず、凡例を付けても学習の負担が大きい（手順2 の末尾の制約）
- 対象が概念や組織であり、多重度や属性の概念が当てはまらない
- 関係の全体像だけを概観させたい。属性と記号は精読を要する

## 入力の構造

graph: categorical。ノードが実体で属性と識別子を持ち、辺が関係で両端に多重度を持つ。

```yaml
entities:
  - {name: 注文, keys: [注文ID], attributes: [注文日, 顧客ID]}
relationships:
  - {from: 顧客, to: 注文, cardinality: "1:N", label: 行う}
```

## デザインの文法

- 実体は長方形で描き、名前を上部に、属性をその下に列挙する
- 多重度は線の両端に記号で示す。一つの図で一つの記法に統一する
- 主キーを属性の先頭に置き、下線や区切り線で他の属性と区別する
- 関係の名前を線に添え、読む向きが分かるように動詞を一方向で書く

## 作成時のルール

- 用いる記法（IE、IDEF1X など）を図の近くに明記し、必要なら凡例を付ける
- 実体名と属性名は実装の名前と一致させ、表記ゆれをなくす
- 関係の多い実体を中央に置き、線の交差を減らす
- 実装を示す図では、多対多の関係を中間の実体に分解して描く

## やってはいけないこと

- 多重度を省いて線だけで結ぶ
- 複数の記法を混ぜ、同じ記号が違う意味を持つ
- 一枚にすべての実体を詰め込み、属性が読めない大きさにする

## 利用例

- 受注システムのテーブル設計。顧客・注文・明細・商品の関係と多重度を示す
- API の仕様書。リソース同士の参照関係と識別子を示す

## NGパターン

- 属性を省いて実体名と線だけにする。多重度を読む根拠がなく、設計の判断に使えない
- 実体の枠に処理や画面を混ぜる。データの実体でないものに多重度を付けると、意味が定まらない
