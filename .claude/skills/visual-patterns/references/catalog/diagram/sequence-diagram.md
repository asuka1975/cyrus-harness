# シーケンス図

## 定義

主体を上端に横に並べ、各主体から下へ伸びるライフラインの間に、メッセージを上から下の時間順に矢印で描く図である。矢印の上下の位置が順序を、向きが送り手と受け手を表す。処理中の期間はライフライン上の帯で示す。

## 目的

何がどの順に起こり、誰が誰に何を渡すかに答える。ある呼び出しの応答がいつ、どこへ返るかを一目で辿れるようにする。

## どういうときに利用するか

- やり取りの主体が二つ以上あり、主体をまたぐメッセージの順序が主題である
- 一つの場面（ユースケース、障害の再現手順）を、呼び出しと応答の対応まで含めて時間順に説明する

## どういうときに利用してはいけないか

- 主体が一つしかない、条件による分かれ方が多い、または主体が 8 つ以上で矢印が重なるなど、一本の流れとして追えない
- 読み手がライフラインや同期・非同期の矢印の記法を知らず、凡例を付けられない

## 入力の構造

`sequence: categorical` を用いる。各段階が送り手・受け手・内容を持ち、一列の前後関係で並ぶ。categorical はやり取りの主体である。

| 順 | 送り手 | 受け手 | 内容 |
| --- | --- | --- | --- |
| 1 | クライアント | API | 注文を送る |
| 2 | API | 在庫サービス | 在庫を確認する |

## デザインの文法

- 主体は上端に横一列に並べ、最初に送る主体を左端に置き、やり取りの多い主体同士を隣接させる
- 時間は上から下へ流れ、矢印の上下の位置だけが順序を表す。同期の呼び出しは塗り矢印、非同期は開いた矢印、応答は破線で描く
- 処理中の期間はライフライン上の帯で示す。ループや条件の枠は最小限にし、枠の条件を文字で明記する

## 作成時のルール

- 一つの図は一つの場面に絞る。正常系と異常系は図を分ける
- メッセージの文字は動詞を含む短い句にし、矢印ごとに必ず付ける
- 図から読み取ってほしい答え（どの順で何が起きるか）をキャプションに一文で書く

## やってはいけないこと

- 時間の流れを左右や下から上にして、上から下の慣習を崩す
- 一つの図に複数の場面を重ね、どの矢印がどの場面のものかを曖昧にする
- 矢印のラベルを省き、何を渡しているかを読み手に推測させる

## 利用例

- サービス間の呼び出し順序。クライアント・API・在庫サービス・決済サービスの間で、注文処理がどの順で進むかを示す
- 認証フロー。ブラウザ・アプリ・認証サーバーの間で、トークンがどの順で発行され検証されるかを示す

## NGパターン

- 承認金額で段数が変わる承認フローをシーケンス図にする。条件の枠が入れ子になり、どの条件でどこへ進むかが読めない
- 主体が一つのバッチ処理の手順をシーケンス図にする。矢印が自分自身へ戻るだけで、順序は番号付きリストの方が低いコストで読める
