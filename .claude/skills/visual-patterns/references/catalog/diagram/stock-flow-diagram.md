# ストック・フロー図

## 定義

蓄積される量（ストック）を長方形、ストックを増減させる速さ（フロー）を弁付きの太い矢印、フローに影響する変数を細い矢印で描いた図である。システムダイナミクスの記法で、流入と流出の差がストックを変える構造を表す。

## 目的

読み手が「どの量が蓄積し、何がその流入と流出の速さを決めるか」に答えられるようにする。

## どういうときに利用するか

- 在庫・負債・利用者数のように蓄積する量と、その増減を決める要因を示したい
- 流入と流出の差が時間とともに蓄積を変えることを、因果の構造として説明したい
- シミュレーションモデルの構造を、式を見せずに共有したい

## どういうときに利用してはいけないか

- 蓄積と速さを区別する必要がなく、因果の向きで足りる
- 読み手がストックとフローの記法を知らず、凡例でも補えない（手順2 の末尾の制約）
- 流量や蓄積の実際の値を比べさせたい。この図は構造を示し、値を示さない

## 入力の構造

graph: categorical。ノードがストック・フロー・補助変数の種別を持ち、辺が物の流れか情報の影響を表す。

```yaml
stocks: [未解決チケット]
flows:
  - {name: 起票, into: 未解決チケット}
  - {name: 解決, out_of: 未解決チケット, influenced_by: [担当者数]}
```

## デザインの文法

- ストックは長方形、フローは弁の記号を持つ太い二重線の矢印、変数は名前だけで描く
- 物の流れの始点や終点が図の外にある場合は雲の記号で示す
- 変数からフローへの影響は細い矢印で描き、物の流れと線の太さで区別する
- 流れの向きは左から右にそろえる

## 作成時のルール

- ストック・フロー・変数の記号の意味を凡例に書く
- ストックは「ある時点に数えられる量」、フローは「単位時間あたりの量」で書き分ける
- 図から読み取ってほしい構造（何が蓄積を増やし、何が減らすか）を本文に一文で書く

## やってはいけないこと

- 蓄積されない変数をストックとして描く
- 情報の影響の矢印を物の流れと同じ太さで描く
- 実際の数値や推移を図に書き込み、構造の図を値の図に見せる

## 利用例

- サポート窓口の未解決チケット。起票の速さと解決の速さが未解決数をどう変えるかを示す
- 技術的負債の蓄積。負債を増やす要因と返済の速さを決める要因を示す

## NGパターン

- フローを使わず、ストック同士を細い矢印で結ぶ。蓄積と速さの区別が消え、因果の向きの図と変わらない
- 変数を 30 以上並べた完全なモデル図。読み手が辿れず、説明したい構造が埋もれる
