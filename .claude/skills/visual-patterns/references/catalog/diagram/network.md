# ネットワーク図

## 定義

項目をノード、関係を線で描き、つながりの全体の形を見せる図である。配置は力学モデルなどの自動レイアウトで決め、つながりの多いノードが中心に、密に結ばれたノード群が近くに集まる。ノードの大きさや色で、つながりの数やグループを重ねることがある。

## 目的

読み手が「どこが密で、何が中心にあり、何が孤立しているか」に答えられるようにする。個々の関係ではなく、関係の集まりが作る形が答えである。

## どういうときに利用するか

- 人・システム・文書などの相互参照で、中心や密集を見つけさせたい
- ノードが数十以上あり、関係を列挙しても全体像が伝わらない（手順2 の「段階・主体・部分とその関係」の行）
- まとまりや孤立を発見させ、詳細は本文で述べたい

## どういうときに利用してはいけないか

- 関係の種類やラベルを読ませたい。線が多く、ラベルを載せられない
- 正確な値（つながりの数）を比べさせたい。大きさや密度は目安にしかならない
- 配置が自動で決まることを読み手が知らず、位置や距離を意味として読む恐れがある

## 入力の構造

graph: categorical。ノードが項目、辺が関係。ノードにグループの属性を持たせてよい。

```yaml
nodes:
  - {id: 認証, group: 基盤}
  - {id: 注文, group: 業務}
edges: [{from: 注文, to: 認証}]
```

## デザインの文法

- 関係は線で結ぶ。向きがある場合だけ矢印にし、向きがなければ線のままにする
- 配置は自動レイアウトに任せ、密に結ばれたノードを近くに置く
- つながりの数をノードの大きさに、グループを色に対応づけ、凡例を付ける
- 線は細く、ノードより薄い色にして、形が線に埋もれないようにする

## 作成時のルール

- 配置が自動で決まり、位置そのものに意味がないことをキャプションに書く
- 注目させるノードやまとまりに色や注釈を付け、どこを見るかを示す
- ノードが多い場合はラベルを主要なノードだけに付ける
- 図から読み取ってほしい形（中心、密集、孤立）を本文に一文で書く

## やってはいけないこと

- 自動配置の上下左右に意味を読ませる説明をする
- ノードや線から正確な数値を読ませようとする
- 全ノードにラベルを付けて、文字が線と重なる

## 利用例

- サービス間の呼び出し関係。呼び出しが集中するサービスと孤立したサービスを示す
- 文書の相互参照。参照が集まる文書と、参照されない文書を示す

## NGパターン

- 数百のノードを一枚に収めた毛玉。線が重なり、密度も中心も読めない
- 関係の種類を線の色で 6 種以上に分ける。全体像より凡例の照合に注意が向き、形が読めない
