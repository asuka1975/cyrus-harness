# 目的のメモ

## 目的
新人エンジニアがブランチ運用のルールを身につけ、main に直接 push する事故をなくす。
きっかけは、先月、新人が main に直接 push してしまう事故が2回起きたこと。

## 読者
今年入社の新人エンジニア。Git の commit と push はできるが、ブランチ運用は知らない。
オンボーディング中に、10分ほどかけてじっくり読む。

## 伝えたいこと
main には直接 push せず、作業ブランチを切ってプルリクエストを出し、レビューを受けてからマージする。この流れを守れば、自分の変更で他の人の作業を壊さずに済む。

## 読後の行動
自分で作業ブランチを切り、プルリクエストを出してレビューを受け、承認後にマージできるようになる。

## 種類と形式
解説。社内Wikiに載せる Markdown の文書で、3000字程度（10分で読める分量）。

## 制約
特になし。
