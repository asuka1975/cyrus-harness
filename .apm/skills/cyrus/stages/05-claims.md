# ステージ5: 主張を組み立てる（Claim Analysis）

フェーズ: インタビュー 5/6　成果物: `05-claims.json`　承認: 必要

## ねらい

文書で主張したいことを、**主張の中心（C0）→ それを支える主張 → 根拠となる事実**の木に分解します。
この木が、ステージ6の事実確認とステージ7の論理検証の対象になります。

## 進め方

1. `01-intent.md` の「伝えたいこと」を、検証できる程度に精密にして C0 にする。
2. C0 を支える主張を3つ前後に絞る（読者が一度に覚えておけるのは3〜4個まで。5個を超えると警告が出る）。
3. 各主張について、「なぜそう言えるのか」を掘り下げ、根拠になる**事実**を挙げる。
   - 事実は、誰かが確かめられる形で書く（「多くの人が困っている」ではなく「2025年の社内アンケートで回答者の62%が検索に不満と答えた」）。
   - まだ確かめていない事実でもよい。ステージ6で確かめる。
4. 主張の種類（type）を付ける。
   - `fact`: 事実そのものを主張する / `judgement`: 事実から判断を導く / `proposal`: 行動を提案する / `explanation`: 仕組みや手順を説明する
5. `04-analysis.md` の「論点」に挙げた反論に、どの主張が答えるかを確かめる。答えられていない論点があれば、主張を足すか、ユーザーと相談して範囲外にする。
6. 主張の木を、読者の言葉で3〜5行にまとめてユーザーに見せ、「言いたいことはこれで合っていますか」と確かめる。ユーザーが意図と違うと言ったら、ここで直す。

## 成果物 `05-claims.json`

```json
{
  "main_claim": {"id": "C0", "text": "主張の中心", "premises": []},
  "claims": [
    {"id": "C1", "text": "C0を支える主張", "type": "judgement", "supports": "C0", "premises": ["F1", "F2"]},
    {"id": "C2", "text": "C1をさらに支える主張", "type": "fact", "supports": "C1", "premises": ["F3"]}
  ],
  "facts": [
    {"id": "F1", "statement": "検証できる形の事実", "source_hint": "どこで確かめられそうか"}
  ]
}
```

- `supports`: その主張が支える上位の主張の id。
- `premises`: その主張の根拠になる事実（F）や主張（C）の id。空にはできない。
- id は C1, C2…／F1, F2… の形。循環は禁止（CLI が検出する）。

## 完了条件

- `cyrus check` でエラーが0。
- 主張の木の要約をユーザーに見せて承認をもらい、`cyrus advance --confirmed "…"`。
