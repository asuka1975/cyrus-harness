# ステージ11: 書く（Document Writing）

フェーズ: 組み立て 5/5　成果物: `draft.md`　承認: 不要

## ねらい

これまでの設計どおりに本文を書きます。設計が済んでいるので、ここでは「何を書くか」ではなく「どう書けば読者が楽に読めるか」に集中します。

## 手元に置くもの

- `08-structure.json`（見出しと順序）
- `09-storyline.json`（各節のメッセージとつなぎ）
- `10-detail.json`（表現の種類・図表の spec・新しい用語・字数）
- `07-logic/report.json`（主張ごとの言い切りの強さ）
- `06-facts.json`（数字と出典）
- `03-reader.json`（読者の語彙）
- `references/japanese-style.md`（文章の指針）

## 書き方

1. 雛形 `draft.md` には、見出しと、各節のメッセージが TODO コメントとして入っている。節ごとに TODO を本文に置き換える。
2. **節の最初の文で、その節のメッセージを言う。** 拾い読みする読者は、見出しと段落の最初の文しか読まない。
3. 前の節からのつなぎ（bridge）は、節の冒頭か前の節の最後に1文で入れる。
4. 主張は `report.json` の hedge に合わせて書く。確信度の低い主張を言い切らない。確信度の高い主張を不必要にぼかさない。
   - **弱い前提を、本文に条件として書く。** 主張の確信度を決めている公理（`report.json` の `claims` の `weakest_links`、`weak_premises`）を、日常語の条件にして主張に添える。例:「承認した人が中身を見てから承認しているかぎり、main に入る変更はすべてレビューを通ります」。
   - **確信度が 0.4 未満の主張は、主張として書かない。** ステージ6の手戻りを終えるまで（またはユーザーがこのまま進めると決めたなら）、「まだ確かめていませんが、〜という見方があります」のように、仮説・未確認事項として書く。
5. 数字や事実には出典を添える（文中の括弧か脚注）。`06-facts.json` の statement と数字を一致させる。
   - **数えた事実（`tally` のある事実）は、件数と割合を先に書き、数え方を一言添え、そのあとに例を1つ書く。** 例:「問い合わせ14件のうち9件は、設定を直せば解決しました（設定の誤り）。たとえば…」。例だけを書いて、全体の傾向を言わない。数字は `tally` の `total`・`counts` と一致させる。
6. 新しい用語は、`10-detail.json` で決めた節の、最初に使う文で説明する（「インデックス（検索を速くするための索引）」の形か、「〜を『インデックス』と呼びます」の形）。
7. 図表は、`10-detail.json` の spec どおりに描く（下の「図表の描き方」）。設計にない図表は置かない。置きたくなったら `cyrus back detail` で spec を足す。
8. 見出しの文言とレベルは `08-structure.json` から変えない。変えたくなったら、`cyrus back structure` で設計に戻って直す（`cyrus check` が見出しの一致を検査する）。
9. 文体は `08-structure.json` の `style`（敬体／常体）に合わせる。

## 図表の描き方（visual-patterns の手順8）

描く前に、そのパターンの文書を読みます（`python3 .claude/skills/visual-patterns/scripts/vp_figure.py show <パターンの ID>`）。「デザインの文法」「作成時のルール」「意図の型と手段」に従い、「やってはいけないこと」「NG パターン」を避けます。描き方の詳細は `.claude/skills/visual-patterns/references/render.md` にあります。

- **番号**: 図は設計に現れた順に 図1、図2…、表は 表1、表2…。`cyrus check` が設計と照合します。
- **キャプション**: 図表の直後の段落に「図N: <spec.answer をそのまま>」と書きます。答えの一文がキャプションです。条件・例外・理由は本文で言います。本文から「図Nのように」と参照します。
- **`render: mermaid`**: Mermaid のコードブロックを置き、その直後にキャプションを置く。
- **`render: vega-lite`**: `documents/<slug>/figures/fig-NN.vl.json` に Vega-Lite の仕様を書き、`cyrus figure render` で `fig-NN.png` にする。本文には `![図N](figures/fig-NN.png)` を置き、その直後にキャプションを置く。仕様のファイルは残す（描き直せるように）。
- **`render: markdown-table`**: Markdown の表を置き、その直後にキャプションを置く。
- **`render: image`**（スクリーンショット・写真）: 実物の素材が要ります。ハーネスは作れないので、ユーザーに素材をもらい、`documents/<slug>/figures/` に置いて `![図N](figures/<名前>.png)` で参照し、その直後にキャプションを置く。秘密の情報はダミーに置き換えてもらう。素材が得られないなら `cyrus back detail` で候補を変える。
- 注釈は spec の `drawing` のとおりに。答えが述べる対象は無彩色にしない。強調の色相は図に一つ。
- 描いたら `cyrus figure check` で、設計との照合（キャプションに答えがあるか、描き方が合っているか、画像があるか）を確かめます。
