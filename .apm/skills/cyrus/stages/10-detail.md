# ステージ10: 見せ方を決める（Document Detail Design）

フェーズ: 組み立て 4/5　成果物: `10-detail.json`　承認: 不要

## ねらい

節ごとに、内容を**文章で書くか、箇条書き・表・図・例で見せるか**を決めます。
あわせて、その節で新しく導入する用語と、想定する字数を決めます。書く前に決めておくと、書きながら迷わず、分量も読者の時間に収まります。

## 表現の選び方

| 内容の性質 | 向いている表現 |
| --- | --- |
| 理由・因果・背景（つながりを伝えたい） | 文章（prose） |
| 並列の項目（順序に意味がない、3〜7個） | 箇条書き（list） |
| 順序のある作業 | 番号付きの手順（steps） |
| 複数の対象を複数の観点で比べる | 表（table）。列は6列、行は12行まで |
| 構造・流れ・位置関係（言葉だと長くなる） | 図（figure）。Mermaid で書ける図を優先 |
| 抽象的な説明の理解を助ける | 具体例（example） |
| 注意・補足（読み飛ばしてもよい） | 囲み（callout） |
| コマンド・設定 | コード（code） |

図と表には、**文章ではなく図表にする理由（why）**を必ず書きます。理由を言えない図表は、読者の視線を散らすだけなので入れません。

## 新しく導入する用語（new_terms）

- 読者が知らない語（03-reader.json の `unknown_terms`）を使うなら、最初に使う節の `new_terms` に入れ、1文の定義を書く。
- 1つの節で導入する語は、読者の知識レベルごとの目安（初心者3個・中級者4個・専門家6個）までにする。超えるなら節を分けるか、語を減らす（言い換えられる語は言い換える）。
- ここに入れた語は、ステージ13で「初出で説明されているか」が検査されます。

## 字数

- `target_length_chars` に全体の目標字数を書く。読者の使える時間（time_budget_min）× 読む速さ（初心者400字／分・中級者500字／分・専門家600字／分）が上限の目安。
- 各節の `length_chars` は、その節の役割の重さに比例させる。要約は短く（全体の1割程度）。
