# ステージ2: 背景を共有してもらう（Context Sharing）

フェーズ: インタビュー 2/6　成果物: `02-context/sources.md`（素材は `02-context/` に置く）　承認: 不要

## ねらい

この文書が必要になった発端のプロジェクトや出来事と、それに関係するデータや資料を集めます。
ここで集めた素材が、後の分析・主張・事実確認の材料になります。

## 進め方

1. **資料を先にもらう。** 「関係する資料（ファイル、URL、メモ、チャットのやりとり、数字）があれば共有してください。なければ口頭で大丈夫です」と伝える。
   - ファイルのパスや URL を受け取ったら、あなたが読む（Read / WebFetch）。ユーザーに要約を頼まない。
   - ユーザーが貼り付けたテキストは `02-context/` に `.md` で保存しておくと、後で参照しやすい。
2. **資料を読んでから聞く。** 資料でわからなかったことだけを質問する。よく効く質問は次のとおり。
   - 「そもそも何が起きて、この文書が必要になったのですか」（発端）
   - 「関係者は誰で、それぞれ何を気にしていますか」（利害）
   - 「数字や事例で、手元にあるものはありますか」（根拠の種）
   - 「これまでに試したこと、検討して却下したことはありますか」（反論への備え）
3. **自分で調べられることは調べる。** 公開情報や、リポジトリの中のコードなど、あなたが確かめられるものは聞かずに調べる。
4. 聞いた内容はその都度、短く要約して返し、誤解がないか確かめる。

深追いしすぎないでください。この段階では「材料が揃っているか」が大事で、整理はステージ4で行います。

## 成果物 `02-context/sources.md`

- **提供された素材**: `- 名前: 場所（パスや URL）— 要点1行` の箇条書き。
- **聞き取りメモ**: ユーザーから聞いた事実・経緯・数字・考え。ユーザーの意見と事実は分けて書く（例: 「〔意見〕移行は来期がよい」）。
- **未確認の点**: まだわからないこと。なければ「なし」。
