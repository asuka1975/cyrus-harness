# 因果ループ図

## 定義

変数をノードに置き、一方が増えると他方がどう変わるかを矢印と極性（同方向 +、逆方向 −）で描き、矢印が巡ってできるループを示した図である。ループには自己強化（R）か均衡（B）の印を付ける。

## 目的

読み手が「どの変数が巡り合って、変化を増幅または抑制しているか」に答えられるようにする。

## どういうときに利用するか

- 施策の効果が巡って自分に戻る構造（成長の加速や頭打ち）を説明したい
- 複数の変数が互いに影響し、文章では循環を追えない（手順2 の「段階・主体・部分とその関係」の行）
- ループが自己強化か均衡かを、変数の名前とともに共有したい

## どういうときに利用してはいけないか

- 因果が一方向で、始点から終点へ読める
- 蓄積量と流入出の速さを区別して読ませたい。この図は量の違いを示さない
- 読み手が極性とループの記号を知らず、凡例を読む余裕がない媒体に出す

## 入力の構造

graph: categorical。ノードが変数、辺が因果の向きと極性を持つ。ループに種別を付ける。

```yaml
edges:
  - {from: 利用者数, to: 口コミ, polarity: "+"}
  - {from: 口コミ, to: 利用者数, polarity: "+"}
loops: [{name: R1, type: 自己強化, nodes: [利用者数, 口コミ]}]
```

## デザインの文法

- 矢印は原因から結果へ向け、矢じりの脇に極性を書く
- ループを作る変数を円環状に近く置き、ループの中央に R か B の印を置く
- 遅れがある因果は矢印に二重線を入れる
- 変数名は増減を語れる名詞にし、「良い」「悪い」の形容を含めない

## 作成時のルール

- 極性と R・B の意味を凡例に書く
- ループは 1〜3 本に絞り、説明したい振る舞いに関係しない変数を省く
- 各ループの振る舞いを本文に一文で書く（「利用者が増えるほど口コミが増え、さらに利用者が増える」）

## やってはいけないこと

- 極性を省いて矢印だけにし、増幅か抑制かを読み手に委ねる
- ループにならない一方向の連鎖を無理に閉じる
- 変数名に方向を含め（「売上の減少」）、極性の読み方を混乱させる

## 利用例

- サービスの成長構造。利用者数と口コミの自己強化ループと、容量不足による均衡ループを示す
- 技術的負債の説明。納期の圧力が負債を増やし、負債が開発速度を落として圧力を強める構造を示す

## NGパターン

- 10 本以上のループを一枚に収める。どの変数がどのループに属するか読めず、振る舞いが説明できない
- 極性を色だけで示す。読み手が色の意味を知らず、増幅と抑制を取り違える
