# 樹形図

## 定義

一つの根から下位の項目へ枝分かれする階層を、節と線で描く図である。根を上または左に置き、親から子へ線を引く。同じ深さの項目は同じ段に揃える。各項目はただ一つの親を持つ。

## 目的

何が何の下位にあり、全体がどう枝分かれしているかに答える。根から葉まで辿ると、ある項目がどの系統に属するかも分かる。

## どういうときに利用するか

- 組織・分類・ファイル構成のように、親子関係がはっきりした階層を一望させる
- 深さが 2〜5 段、節が 50 程度までに収まる
- 量や割合ではなく、分かれ方そのものが答えである

## どういうときに利用してはいけないか

- 項目が複数の親に属し、線が交差する
- 各項目の量や割合を正確に読ませる
- 深さが 1 段で、箇条書きで足りる

## 入力の構造

`hierarchy: categorical`。各項目が親を一つ持ち、根だけが親を持たない。

| 項目 | 親 |
| --- | --- |
| 営業部 | 本社 |
| 第一課 | 営業部 |

## デザインの文法

- 根を上に置き、深さを段で揃える。幅が広い場合は根を左に置き、右へ展開する
- 親子は直線か直角の折れ線で結び、交差させない。矢印は使わない
- 兄弟は同じ段に並べる。並び順に意味があれば（序列・五十音など）その順にする
- 節は同じ形・同じ大きさで描く。色は段か系統の区別だけに使う

## 作成時のルール

- 根は一つにする。根が複数ある場合は図を分ける
- 兄弟の並び順を決め、順に意味がなければ均等に扱う
- 深さや幅が規模を超える場合は浅い段だけを示し、下位は別の図に分ける
- 読み取らせたい答え（例: どの系統に属するか）を本文に一文で書く

## やってはいけないこと

- 同じ項目を二箇所に置いて、複数の親を持つように見せる
- 節の大きさや色を変えて、量や重要度を暗示する
- 親子でない項目同士を線で結ぶ

## 利用例

- 組織図（Organisation chart）: 本社から部・課への指揮系統を示し、各課がどの部の下にあるかを答える
- 製品分類: 大分類・中分類・小分類の枝分かれを示す
- ディレクトリ構成: フォルダとその下のファイルの入れ子を示す

## NGパターン

- 兼務者を二つの部の下に置いた組織図。各項目がただ一つの親を持つ前提が崩れ、読み手は線を辿って混乱する
- 売上の大きい部門の節を大きく描いた樹形図。大きさが量を示すと読まれ、階層とは別の問いに答えてしまう
