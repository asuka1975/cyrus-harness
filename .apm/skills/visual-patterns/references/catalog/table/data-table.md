# 表

## 定義

項目を行、属性を列に取り、交差するセルに値を書いた表である。先頭列に項目を特定するキーを置き、読み手がキーで行を探し、列見出しで属性を探して、交差するセルの値を参照する。

## 目的

この項目のこの属性の値は何かに答える。読み手が必要な一つの値を、探し当てて正確に読めるようにする。

## どういうときに利用するか

- 読み方が参照で、読み手は自分に必要な項目の値だけを探す
- 項目が複数あり、同じ属性の集合を持つ。値は正確に読ませる必要がある

## どういうときに利用してはいけないか

- 読み手に通読させる情報で、探す読み方をしない
- 値の大小や傾向、分布の形が答えで、個々の値の正確さは要らない
- 行が 50 を超え、または列が 9 以上あり、紙や一画面で探せない

## 入力の構造

`items: categorical` を用いる。各項目が参照される属性を持つ。属性の尺度は問わない。

## デザインの文法

- 先頭列に項目のキーを置き、読み手が探す順（名前順、番号順）に行を並べる
- 列見出しに属性名と単位を書く。数値は右揃え、文字は左揃えにし、桁をそろえる
- 罫線は行の区切りが分かる最小限にし、交互の塗りや余白で行を追いやすくする

## 作成時のルール

- 一つのセルに一つの値を書く。複数の値が要るなら列を分ける
- 空欄を作らない。値がない場合は「—」のように明記し、意味を注記する
- 表から探してほしい値が何かをキャプションに一文で書く

## やってはいけないこと

- 行の並びを意味のない順にして、読み手に全行を走査させる
- 列ごとに単位や表記を変え、同じ属性の値を見比べにくくする
- セルに長文や複数の値を詰め、参照する値を探しにくくする

## 利用例

- 環境ごとの接続先ホスト名とポート番号。開発・検証・本番の行から、必要な環境の接続先を探す
- API のエラーコード一覧。コードをキーに、意味と対処を参照する

## NGパターン

- 30 のエンドポイントの平均応答時間の大小を表にする。読み手が数値を一つずつ読んで比べる負担を負い、傾向が見えない
- 三段階の移行手順を表にする。通読する手順を探す読み方に置き換え、順序が見えにくくなる
