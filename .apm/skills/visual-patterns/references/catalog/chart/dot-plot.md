# ドット・プロット

## 定義

カテゴリを縦に並べ、各カテゴリの最小値と最大値（必要なら中央値など数点）を共通の数値軸上の点で描き、点の間を線分で結ぶ図である。線分の長さが値の幅を表す。

## 目的

各カテゴリの値がどの範囲に収まり、幅はカテゴリ間でどう違うかを答えられるようにする。

## どういうときに利用するか

- カテゴリごとの値の幅（最小・最大）を並べて比べたい
- 幅の両端に加えて、中央値などの代表点を少数示したい
- カテゴリが三十以下で、一行ずつ読める

## どういうときに利用してはいけないか

- カテゴリあたりの点が多く、重なって読めない
- 幅の内側で値がどう散らばっているかが答えに含まれる
- 両端の値を正確に読ませる

## 入力の構造

`items: categorical + quantitative`。各カテゴリが最小値と最大値（必要なら中央値）を持つ。

| カテゴリ | 最小 | 中央値 | 最大 |
| --- | --- | --- | --- |
| API-A | 40 | 85 | 320 |
| API-B | 60 | 210 | 980 |

## デザインの文法

- 数値軸は横に一本置き、全カテゴリで共有する
- 点の種類（最小・最大・中央値）は色または塗りで区別し、凡例に示す
- 線分は点より細く薄い色にし、幅を示す補助に徹する
- カテゴリは幅の広い順か中央値の順に並べる

## 作成時のルール

- 一行あたりの点は五つまでにする
- 点の種類が二つ以上ある場合は、凡例を図の近くに置く
- 軸は 0 を含めなくてよいが、範囲を切った場合は目盛で示す
- 読み取ってほしい差（どのカテゴリが広いか）をキャプションに一文で書く

## やってはいけないこと

- 線分を棒のように塗りつぶし、長さを量と誤読させる
- 点の種類を色だけで区別して凡例を省く
- カテゴリごとに軸の範囲を変える

## 利用例

- API ごとの応答時間の最小・最大を並べ、幅の広い API を示す
- 製品ごとの価格帯（最低価格と最高価格）を並べ、価格帯の重なりを示す

## NGパターン

- 一行に二十点を並べる。点が重なり、両端も中央も読めない
- 最小と最大の点を同じ色にして凡例を省く。どちらが最大か読み手が迷う
