# ロリポップチャート

## 定義

項目ごとに値の位置へ点を置き、基準線から点まで細い線でつなぐ図である。点の位置が値を示し、線は項目名と点を結び付ける案内役である。点が主役のため、値の軸をゼロ以外から始めても、長さの比で読ませずに済む。

## 目的

どの項目が大きいか、どのくらい違うかを、点の位置で答えられるようにする。値の順に並べれば、何番目かも答えられる。

## どういうときに利用するか

- 値そのものを点で目立たせたい
- 項目が多く、太い棒を並べると図が重くなる
- 値の範囲の一部だけを見せたい（軸をゼロから始められない）

## どういうときに利用してはいけないか

- 値の差が小さく、点の位置の差が読み取れない
- 同じ項目に重ねる系列が三つ以上ある
- 個々の値を正確に読ませる必要がある

## 入力の構造

`items: categorical + quantitative`。項目名と数値の組を一行ずつ持つ。

| エンドポイント | 平均応答時間（ms） |
| --- | --- |
| /orders | 420 |
| /users | 95 |

## デザインの文法

- 点を値の位置に置き、線は点より細く薄い色にする
- 項目は値の順に並べる。横置きなら項目名を左、点を右に置く
- 点の大きさは一定にし、大きさに意味を持たせない
- 系列は点の色で区別し、凡例を点の近くに置く

## 作成時のルール

- 点の直径は線の太さの三倍以上にし、点が主役と分かるようにする
- 軸の起点をゼロ以外にする場合は、起点の値を軸とキャプションに明記する
- 値のラベルを付けるなら点のそばに置く
- 読み取ってほしい差を一文で添える

## やってはいけないこと

- 線を太くし、長さで量を読ませる
- 点の大きさを値で変える
- 点と項目名を離し、どの点がどの項目か追えなくする

## 利用例

- 五十の API エンドポイントの平均応答時間を値の順に並べ、遅い上位を示す
- 部署ごとの平均勤続年数（10〜20 年の範囲）を比べる
- 店舗ごとの顧客満足度（3.5〜4.8 点の範囲）を比べる

## NGパターン

- 太い線の先に小さな点を置く: 線の長さが主役になり、起点がゼロでないとき差を誇張する
- 二十系列の点を同じ行に重ねる: 点が重なり、どの系列の値か区別できない
