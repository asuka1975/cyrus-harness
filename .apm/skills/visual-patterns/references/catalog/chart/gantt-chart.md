# ガントチャート

## 定義

横軸に時間を取り、作業ごとに一行を割り当て、開始から終了までを横棒で描く図である。
節目はひし形などの印で示し、作業の間の依存は棒をつなぐ矢印で示す。

## 目的

何をいつからいつまで行い、何が並行し、何が何の完了を待つか、節目はいつかに答える。

## どういうときに利用するか

- 複数の担当や作業が並行する計画を、関係者に共有したい
- 作業の順序と依存を、時期とともに見せたい
- 計画に対する進捗や遅れを、同じ図で追いたい

## どういうときに利用してはいけないか

- 作業が一つの流れで、並行も依存もない（番号付きリストで足りる）
- 時期が未定で、棒の長さを決められない
- 作業の中の条件による分かれ方が主題である

## 入力の構造

`items: categorical + temporal`。各作業は名前、開始、終了を持つ。依存があれば先行作業を持ち、形は graph になる。
```yaml
- {task: 要件定義, start: 2026-04-01, end: 2026-04-30, group: 準備}
- {task: 設計, start: 2026-05-01, end: 2026-06-15, group: 開発, after: 要件定義}
```

## デザインの文法

- 横軸は時間。週や月の目盛りを打ち、今日の位置に縦線を引く
- 一行に一作業。開始の順に上から並べ、段階ごとにまとめて見出し行を置く
- 棒の左端が開始、右端が終了。節目は幅のない印で示す
- 依存は先行作業の右端から後続作業の左端へ矢印を引く

## 作成時のルール

- 作業名は左端の列に書き、棒の位置だけで作業を識別させない
- 進捗を示す場合は棒の中を塗り分け、計画の棒と実績の棒を区別する
- 依存の矢印は主要なものに絞り、交差を減らす

## やってはいけないこと

- 行の順序を時系列と無関係に並べ、並行関係を読みにくくする
- 作業の重要度や工数で棒の太さや色を変え、期間の読みを乱す
- 期間が未定の作業に仮の棒を引き、確定した計画に見せる

## 利用例

- システム移行作業の期間と並行関係を示し、どの作業が同時に走るかを見せる
- 製品リリースまでの開発・検証・告知の段階を並べ、節目と依存を示す

## NGパターン

- 20 の作業がすべて直列で、棒が階段状に並ぶ。並行も依存もなく、図から読める情報が作業の順番しかない
- 依存の矢印を全作業に引き、線が交差して棒が隠れる。何が何を待つかがかえって読めない
