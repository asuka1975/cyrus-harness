# ツリーマップ

## 定義

全体を一つの矩形とし、親子関係に沿って矩形を入れ子に分割した図である。各矩形の面積が全体に占める量を表し、入れ子の包含が階層を表す。同じ親に属する矩形は隣り合って配置される。

## 目的

全体は何から成り、どの区分とどの項目がどれだけを占めるかに答える。階層をまたいで、量がどこに集中しているかにも答える。

## どういうときに利用するか

- 区分の下に項目があり、両方の割合を一つの図で示す
- 項目が数十あり、上位の少数が大半を占める
- 全体の中で特に大きい項目を見つけさせる

## どういうときに利用してはいけないか

- 面積の差が小さく、どちらが大きいか読めない
- 階層が深い、または項目が多すぎて、矩形が細かくなり読めない
- 紙や静止画で、小さな矩形の項目名を読ませる必要がある

## 入力の構造

hierarchy で、各項目が親を持ち、categorical の名前と quantitative の値を持つ。親の値は子の値の合計とする。
```yaml
- {parent: null, name: 予算, value: 1000}
- {parent: 予算, name: 開発部, value: 600}
- {parent: 開発部, name: 人件費, value: 450}
```

## デザインの文法

- 矩形は面積が値に比例する。縦横比を正方形に近づけ、面積が読めるようにする
- 同じ親の子は左上から大きい順に並べる
- 色は最上位の区分ごとに一つ。下位は同じ色の濃淡にする
- 階層は余白と枠線の太さで示す。上位ほど枠を太く、余白を広くする

## 作成時のルール

- 階層は 3 段までにする。深い階層は上位で切り、下位は別図にする
- ラベルは面積に応じて省略する。読めない矩形には書かない
- 最上位の区分名を矩形の上辺に置き、何の内訳かを示す
- 読ませたい項目の値を添え書きに書き、面積だけに頼らない

## やってはいけないこと

- 値に比例しない面積にする
- 階層ごとに別の色体系を使い、どの色が区分を表すのか分からなくする
- 面積と色の両方に別の量を割り当て、読み手に二つの符号化を同時に読ませる

## 利用例

- ディスク使用量をディレクトリの階層で示し、容量を占めているディレクトリを見つける
- 予算を部門別・費目別に示し、どの部門のどの費目が大きいかを見せる

## NGパターン

- 階層のない 5 項目の構成を矩形で示す。入れ子の意味がなく、面積の比較が角度や長さより粗いだけになる
- 500 項目を一つの図に収める。矩形が細かくなり、ラベルが消え、読み手は色の塊しか読み取れない
