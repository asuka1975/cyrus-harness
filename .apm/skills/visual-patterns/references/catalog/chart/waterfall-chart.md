# 滝グラフ

## 定義

起点の値から順に増減の要素を足し引きし、終点の値に至る過程を棒で描いた図である。各要素の棒は直前の累計の位置から浮かせて描き、長さが増減の量を、色が正負を表す。起点と終点の棒は基線から立てる。

## 目的

全体は何から成り、各要素が全体をどれだけ増やし、または減らしたかに答える。起点から終点までの差がどの要素によるものかにも答える。

## どういうときに利用するか

- 構成要素にマイナスの値があり、全体がそれらの足し引きで決まる
- 期首残高から期末残高への増減要因を順に示す
- 売上から原価・経費を差し引いて利益に至る過程を示す

## どういうときに利用してはいけないか

- 要素がすべて正で、順序に意味がない
- 要素が多く、浮いた棒が細かくなって個々の増減が読めない
- 読み手が浮いた棒の読み方を知らず、説明を添えられない

## 入力の構造

items で、各項目が要素を識別する categorical 属性と、増減を符号付きの quantitative で持つ。項目は足し引きする順に並べ、起点と終点を含める。
```yaml
- {step: 期首残高, value: 1200, kind: total}
- {step: 仕入, value: -500, kind: delta}
```

## デザインの文法

- 横軸は要素を足し引きの順に並べる。縦軸は量で、原点を 0 にする
- 起点・終点と途中の小計は基線から立て、増減の要素は累計の位置から浮かせる。浮いた棒の端同士は細い線でつなぐ
- 増加と減少を別の色にし、起点・終点・小計は第三の色にする
- 各棒に増減の値を書く。浮いた棒は長さを比べにくい

## 作成時のルール

- 要素は 12 までにし、小さな要素は「その他」にまとめる
- 要素の順は、計算の順か、増減の大きい順のどちらかに揃える
- 途中の小計（粗利など）を入れ、累計の節目を明示する
- 起点から終点への差を、キャプションに一文で書く

## やってはいけないこと

- 増減の棒を基線から立て、累計の位置から浮かせない
- 正負の色を途中で入れ替える
- 縦軸の原点を 0 以外にして、起点と終点の高さをゆがめる

## 利用例

- 営業利益の増減要因。前期の営業利益から売上増・原価増・経費減を順に足し引きし、当期に至る
- 損益計算書。売上高から売上原価・販管費を差し引き、粗利・営業利益の小計を経て当期利益に至る

## NGパターン

- 五つの費目がすべて正の支出を滝で描く。浮いた棒にする理由がなく、読み手は足し引きの意味を探す
- 増減の値を書かずに浮いた棒だけを並べる。基線がないため長さを比べられず、読み手は増減の大きさを読み誤る
